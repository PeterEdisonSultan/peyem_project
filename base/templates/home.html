Contexte & Enjeux

La Problématique

Malgré l'essor du e-commerce, l'encaissement reste le goulot d'étranglement du e-commerce haïtien.

Un écosystème fragmenté et manuel

Au cours des dernières années, le commerce en ligne en Haïti, notamment à travers les réseaux sociaux, a connu une croissance remarquable soutenue par la généralisation des smartphones, l’accès accru à Internet et l’utilisation d’applications telles que WhatsApp, Instagram, Facebook et, plus récemment, TikTok, devenues de véritables plateformes de vente pour de nombreux commerçants.


Cependant, l’essor du commerce électronique formel, c’est-à-dire la vente directe de produits et services via des sites web, reste entravé par une difficulté majeure : l’absence d’un système de paiement intégré, fluide et unifié.

APIs Inexistantes ou Multiples

Les développeurs font face à un vide technologique : souvent, les APIs de paiement sont inexistantes ou inaccessibles. Lorsqu'elles existent, elles obligent à intégrer laborieusement plusieurs systèmes distincts simultanément pour couvrir le marché.

Barrière Administrative (Accès API)

L'obtention des clés API officielles auprès des grands opérateurs est un processus long, bureaucratique et souvent inaccessible pour les petites PME ou startups locales.

Processus Manuel & Risqué

Les vendeurs doivent vérifier manuellement sur leur téléphone la réception de chaque paiement. Cela entraîne des délais, des erreurs humaines et des risques de fraude.

Frein au E-commerce Formel

Faute de solution technique "clé en main" et facile à intégrer, la majorité des entrepreneurs renoncent à créer de véritables sites web transactionnels, restant confinés à la vente informelle sur les réseaux sociaux.

Notre Proposition

La Solution PEYEM

Une architecture modulaire conçue pour répondre aux besoins techniques et commerciaux de l'écosystème haïtien.

Agrégation Mobile & Bancaire

Une API centrale unifiant les portefeuilles mobiles (MonCash, NatCash) et visant l'intégration des institutions bancaires locales (Unibank, Sogebank, BUH, Capital Bank) via un protocole unique.

Expérience Client Optimisée

Une interface de caisse (Checkout) fluide qui permet aux acheteurs des sites de nos clients de finaliser leurs achats en toute confiance, quel que soit le moyen de paiement choisi.

Intégration via SDK JavaScript

Une implémentation technique simple impliquant quelques lignes de code à copier, flexible et moderne. Grâce à notre SDK JavaScript, PEYEM s'intègre aisément dans des environnements variés (HTML pur, PHP, Python/Django) sans refonte du site existant.

Dashboard Analytique

Un tableau de bord complet offrant aux marchands une vue graphique des revenus, un historique filtrable des transactions en temps réel, la gestion autonome de leurs comptes ainsi qu'un portail développeur complet comprenant toutes les instructions et codes nécessaires à l'implémentation.

Sécurité & Confidentialité

Protection rigoureuse des échanges entre l’API et les utilisateurs grâce à des protocoles sécurisés, garantissant que les données sensibles ne transitent jamais en clair.

Compatibilité Multi-plateforme

Une conception Responsive Design garantissant l'accessibilité du système aussi bien sur ordinateur que sur mobile pour une expérience fluide pour tous les utilisateurs.

Ingénierie

Architecture & Réalisation

Détails techniques, choix d'implémentation et périmètre du prototype académique.

Stack Technologique

Le système repose sur une architecture robuste et standardisée :

  • Backend : Framework Django (Python) pour la gestion sécurisée des données et l'API REST.
  • Frontend : HTML5, CSS3, et JavaScript Vanilla (sans framework lourd) couplé à Bootstrap 5 pour le responsive design.
  • Base de données : SQLite (Prototype) / Compatible PostgreSQL (Prod).
Périmètre du Prototype & Limitations

1. Simulation (Sandbox) : En raison des délais d'accès aux API réelles (MonCash/NatCash), ce projet utilise des simulateurs internes pour démontrer la faisabilité du flux financier.

2. Fonctionnalités (Time-Boxing) : Certaines fonctions avancées (remboursements, reçus PDF dynamiques) ont été reportées à la version ultérieure (V2) pour prioriser le cœur du système de paiement.

3. Audit de Sécurité : Bien que les protections Django (CSRF, Auth) soient actives, aucun test de pénétration rigoureux n'a été effectué pour une certification de production.

4. Optimisation Interface (UI) : L'interface, bien que construite sur Bootstrap, est optimisée pour un affichage Desktop. L'adaptation complète aux mobiles et tablettes (Responsive absolu) reste à perfectionner.

5. Déploiement Local : Le système n'est pas hébergé sur un serveur cloud de production. L'accès public est assuré via un tunnel sécurisé Ngrok connecté à l'environnement de développement local.

6. Tests d'Intégration SDK : Le script d'intégration (bouton de paiement) fonctionne dans l'environnement de démo, mais n'a pas subi de tests extensifs de compatibilité (cross-browser) pour garantir une stabilité totale sur tout type de site tiers.
